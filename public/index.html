🤨 You should not be here!

But since you've found it, here are the endpoints:

  • / - the default route. It serves this HTML file along with the CSS & JS from /public - basically this page!
  • /check - a health check. Returns JSON so you can confirm the server is running
  • /api/tasks - the example CRUD resource. Copy its shape for your own resources:
    • GET /api/tasks - list all tasks
    • GET /api/tasks/:id - get one task
    • POST /api/tasks - create a task
    • PUT /api/tasks/:id - replace a task (all fields)
    • PATCH /api/tasks/:id - update part of a task (some fields)
    • DELETE /api/tasks/:id - delete a task
  • GET /api/protected - 🔒 a protected test route. Needs either our login cookie or an Auth0 token (Authorization: Bearer <token>) or it returns 401. Handy for confirming auth works.
  • /auth - everything about who the user is. There are two ways in: an email + password account we manage ourselves, or a social login handled by Auth0. Both end up as a row in the same users table.
    • POST /auth/signup - create an account with a username, email & password. Sets the login cookie, so signing up logs you in
    • POST /auth/login - trade an email/username & password for that same cookie
    • POST /auth/logout - clear the cookie
    • POST /auth/auth0 - 🔒 Auth0 token required. After a social login, create the user if they don't exist yet and return their row
    • GET /auth/me - 🔒 either credential. The logged-in user's row — this is how the frontend answers "am I still logged in?" after a refresh

Note: this is a boiler Node.js & Express setup

please customize it to fit your specific application
